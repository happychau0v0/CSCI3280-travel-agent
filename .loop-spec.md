## CURRENT STATE (read before first iteration)

MapLibre migration is in progress. The app currently has a feature flag:
- `?map=maplibre` — uses new MapLibre MapView (work in progress)
- default / `?map=legacy` — uses old react-globe.gl + react-leaflet (still working)

**What's been built so far** (see `frontend/src/components/MapView.jsx`):
- Globe mode: Fibonacci dot grid (15k pts filtered to land-only via countries.geojson), flight arcs, pins
- Hotels mode: hotel pins with active/default styling, airport badge for outlier airports
- Days mode: activity pins with active/dim states, route polylines from `transport_to_next.polyline`

**Known bug (MIG3)**: When switching panels HOME→HOTELS, the MapView background map does NOT
fly to the destination. `window.__mapInstance.flyTo(...)` works manually. The React `useEffect`
tracking the `focus` prop is not triggering the call. Debug suggests the issue is either:
- `loaded` React state not being true when the effect fires after a prop change
- `focus` prop object identity not changing (memo returning same ref)
- The effect running but its `map.flyTo` call being overridden by another effect

**Fix approach for MIG3**: In `MapView.jsx`, instead of (or in addition to) the `focus` useEffect,
add a direct `map.on("idle")` one-shot callback after mode changes, OR use a `useCallback`-based
imperative flyTo called from App.jsx via the `mapViewRef` when the panel changes.

The `mapViewRef` already exposes `{ flyTo, resetToGlobe, getMap }` via `useImperativeHandle`.
In App.jsx, add a `useEffect` that watches `menu.state.panel` and calls
`mapViewRef.current?.flyTo(...)` directly when switching to HOTELS or DAYS. This bypasses
the prop-driven focus mechanism entirely and is more reliable.

**Architecture constraint**: Once MIG3-MIG6 are done, `?map=maplibre` should be the default.
The legacy GlobeView+Leaflet path stays available via `?map=legacy` for one release.

## MIGRATION OBJECTIVES (complete before OBJ1–OBJ6)

### MIG3 — Fix panel flyTo bug

**Problem**: MapView's `useEffect([focus, loaded, mode, ...])` is not reliably calling
`map.flyTo()` when the panel switches to HOTELS or DAYS.

**Fix**: In `App.jsx`, add an imperative panel-switch effect that calls the ref directly:

```js
// In App.jsx, after mapViewRef declaration:
useEffect(() => {
  if (!useMapLibre) return;
  const dest = currentItinerary?.flight;
  if (!dest?.to_lat || !dest?.to_lng) return;
  if (menu.state.panel === "HOTELS") {
    mapViewRef.current?.flyTo({ lat: dest.to_lat, lng: dest.to_lng, zoom: 12 });
  } else if (menu.state.panel === "DAYS") {
    mapViewRef.current?.flyTo({ lat: dest.to_lat, lng: dest.to_lng, zoom: 13 });
  } else if (menu.state.panel === "HOME" || menu.state.panel === "FLIGHTS") {
    mapViewRef.current?.resetToGlobe();
  }
}, [menu.state.panel, useMapLibre, currentItinerary]);
```

The `flyTo` method on the ref already handles `{ lat, lng, zoom }` correctly (see MapView.jsx
`useImperativeHandle`). Also keep the existing `focus` prop for backward compat.

**Verify**: In Playwright at `?map=maplibre`, inject test itinerary (Tokyo), switch to HOTELS,
confirm `window.__mapInstance.getZoom()` ≥ 10 and center is near Tokyo (~35.6°N, 139.6°E).

### MIG4 — DAYS mode complete

DayMiniMap is already hidden in PanelDays when `useMapLibre=true`. Verify:
- Activity pins render with correct numbering (1, 2, 3...)
- Active pin (activeActivityIdx) shows amber, rest show cyan
- Route polylines from `transport_to_next.polyline` show as dashed cyan

For fitting to activities bounds, add a `useEffect` in MapView.jsx that watches `activities` in
days mode and calls `map.fitBounds(computedBounds, {padding: 60})`:

```js
// In MapView.jsx, add after the hotel flyTo effect:
useEffect(() => {
  const map = mapRef.current;
  if (!map || !loaded || mode !== "days") return;
  const pts = (activities || []).filter(a => a.lat != null && a.lng != null);
  if (pts.length < 2) return;
  const bounds = computeBounds(pts.map(a => [a.lat, a.lng]));
  if (!bounds) return;
  const padding = 80;
  map.fitBounds(
    [[bounds.minLng, bounds.minLat], [bounds.maxLng, bounds.maxLat]],
    { padding, duration: reducedMotion ? 0 : 1400, essential: true }
  );
}, [activities, loaded, mode, reducedMotion]);
```

Import `computeBounds` from mapUtils.js.

## ARCHITECTURE CONSTRAINTS (do not violate)

- MapLibre GL JS v5 is the ONLY map library. No Leaflet, no globe.gl, no react-globe.gl.
- MapLibre's globe→Mercator auto-transition happens at zoom 6–12. Do not fight this.
- The `.panel-grid` sits at z-index 30 above the full-bleed map. The map is always rendered full-screen behind all panels.
- LLM tools are registered in `backend/app/llm.py` TOOL_DISPATCH dict and declared in the tools list passed to the OpenRouter API call.
- For new tools, follow existing pattern: add to `TOOL_DISPATCH`, add a JSON Schema entry to `tools` list, and add a handler function in `backend/app/tools/`.
- The SSE stream emits `navigate`, `request_input`, `tool_start`, `tool_end`, `done` events — frontend handles these in `streamChat` onEvent.

### OBJ1 — Globe→Street-map zoom with destination centered

**Behaviour wanted:**
When switching from HOME/FLIGHTS panel (globe view, zoom ~1.5) to HOTELS or DAYS panel (city view), MapLibre should animate: globe → zoom in over destination city → arrive at zoom 13 with destination lat/lng centered. The center-panel map then shows the full city at street level. Other panels (left list, right summary) must not shift layout.

**How to implement:**
1. In `MapView.jsx`, ensure the `focus` prop (`{lat, lng, zoom}`) triggers `map.flyTo({center:[lng,lat], zoom, duration:2200, essential:true})`.
2. In `App.jsx`, when `activePanel` changes to `"HOTELS"` or `"DAYS"`, pass a `focus` prop derived from the itinerary destination's geocoded lat/lng (stored in state from `geocode_city` tool result).
3. The `.panel-grid-center-zoom-in` animation (scale 0.55→1.0 over 900ms starting at 1400ms) creates the "zoom through Earth" illusion — keep this intact. Do NOT change panel layout CSS.
4. Verify destination is centered (not defaulting to 0,0 or previous view).

**Update `backend/app/prompts.py`** system prompt to tell the LLM it can use `toggle_setting` and `submit_trip_form`.

### OBJ5 — Days map: 2 pins only (active leg start→end), live route

**Behaviour wanted:**
When user selects activity index `i` on the DAYS panel, the map shows exactly 2 pins:
- Pin A: activity `i` (amber/active)
- Pin B: activity `i+1` (teal/dim), or the hotel if `i` is the last activity of the day

Map flies to fit these 2 points. A polyline (from Google Directions API) is drawn between them.

**Implementation:**
1. In `MapView.jsx`, extend "days" mode to accept `activeLeg: {from: {lat,lng,label}, to: {lat,lng,label}, routePolyline?: string}` prop instead of all activities.
2. In `App.jsx`, derive `activeLeg` from `(activeActivityIdx, currentItinerary.days[activeDayIdx].activities)`. Route polylines are already stored from the LLM's `get_directions` calls during day planning — use those.
3. Decode polyline with `decodePolyline` from mapUtils.js and render as a GeoJSON `LineString` layer on the MapLibre map.
4. On `activeLeg` change, `map.flyTo` to the midpoint/bounds of the 2 pins (use `computeBounds` from mapUtils.js + padding).
5. Remove old "show all day activities" logic for days mode.

### OBJ6 — Flight globe updates arcs for selected flight option

**Behaviour wanted:**
- Non-stop flight selected: 1 arc (origin → destination)
- 1-stop flight selected: 2 arcs (origin → layover, layover → destination)
- Arc update plays a 300ms fade-out on old arcs before new ones appear.

**Implementation:**
1. Ensure `selectedFlightIdx` state in `App.jsx` is wired to each flight option's select/pick action.
2. Derive `flightArcs` from `flights[selectedFlightIdx]`: if `stops === 0`, one arc; if `stops > 0`, build N+1 arc segments using `layovers: [{iata, lat, lng}]`.
3. Check `backend/app/tools/flights.py` — if layover coords are missing, add them by geocoding the layover IATA code via `geocode_city`.
4. Pass updated `arcs` prop to `MapView`. MapLibre re-renders the GeoJSON source on prop change.
5. Add `line-opacity-transition: {duration: 300}` to the arc layer paint property for smooth fade.
